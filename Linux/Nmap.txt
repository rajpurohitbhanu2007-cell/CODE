# Network Reconnaissance and Gateway Service Assessment Report

**Date:** 12 August 2026
**Target Network:** `10.5.0.0/24`
**Gateway:** `10.5.0.1`
**Scanning Host:** `10.5.0.90` (`git-H61H2-MV`)
**Tool:** Nmap 7.80, cURL, OpenSSL
**Assessment Type:** Local network/service reconnaissance

---

## 1. Executive Summary

A network reconnaissance assessment was performed from host `10.5.0.90` against the local `10.5.0.0/24` network.

Nmap host discovery identified **44 active hosts** on the `/24` network.

The local scanning system, `10.5.0.90`, was also assessed. Nmap's default 1,000 TCP ports were all reported as **closed**, indicating that no commonly scanned TCP services were listening on the host at the time of testing.

The network gateway at `10.5.0.1` initially did not respond to Nmap's default host-discovery probes. A subsequent scan using `-Pn` confirmed that the gateway was reachable.

A full TCP port scan of the gateway identified:

* **TCP/808 — Open**
* **TCP/9512 — Open**
* Most other TCP ports — **Filtered**
* One additional port — **Closed**

Further HTTP testing established that TCP/808 provides an HTTP service that redirects clients to HTTPS on TCP/9512.

The HTTPS service on TCP/9512 was identified as a **Fortinet FortiGate administration interface** based on the returned HTML, including Fortinet-specific page elements and cookie names.

No authentication bypass, exploitation, password testing, or modification of the gateway was performed.

## 12. Security Observations

### 12.1 Management Interface Exposure

The FortiGate management interface is reachable from the local `10.5.0.0/24` network on TCP/9512.

This is not necessarily a vulnerability. It is common for network administrators to manage a FortiGate through an internal management interface.

However, management access should ideally be restricted to trusted management networks or authorized administrator hosts.

### 12.2 HTTP Redirect

TCP/808 accepts HTTP connections and redirects them to HTTPS.

This is preferable to serving the administration interface directly over plaintext HTTP.

### 12.3 Self-Signed Certificate

The HTTPS service uses a self-signed certificate.

This can cause browser certificate warnings unless the certificate is trusted by the administrative workstation.

For production environments, administrators should consider using a properly managed certificate where appropriate.

### 12.4 Filtering

The majority of TCP ports on the gateway were filtered.

This suggests that the gateway/firewall is limiting unsolicited TCP connections to services that are not intentionally exposed.

### 12.5 Authentication

The management interface presents a username/password login and contains support for a token-code field.

The assessment did **not** attempt authentication, password guessing, credential testing, authentication bypass, or exploitation.

## 13. Limitations

The assessment did not determine:

* Exact FortiGate model.
* Exact FortiOS version.
* UDP service exposure.
* Configuration of firewall policies.
* Administrator accounts.
* Password strength.
* MFA configuration.
* Vulnerability status of the installed FortiOS version.
* Internal firewall rules.
* Services accessible from networks other than `10.5.0.0/24`.

Therefore, the assessment should be considered a **network/service reconnaissance assessment**, not a complete penetration test or configuration audit.

---

## 14. Recommended Next Steps

If this is an authorized assessment of the FortiGate, recommended next steps are:

1. **Identify the exact FortiOS version** from the administrative interface.
2. Compare that version against Fortinet's current security advisories.
3. Confirm that administrative access is restricted to trusted networks.
4. Confirm that WAN-side administrative access is disabled unless explicitly required.
5. Review administrator accounts and MFA configuration.
6. Review the TLS certificate configuration.
7. Review firewall policies for unnecessary management exposure.
8. Consider restricting TCP/9512 to designated administrator IP addresses.
9. Review logging and monitoring for administrative access.
10. Keep FortiOS updated according to the organization's maintenance and security policy.
